About this demo SWCanvas renders rotated and scaled text via BitmapText.js; bounded LRU keeps ≤ K atlases resident under N > K stress; placeholder rectangles paint until atlases arrive.

What it shows. Dynamic, on-demand atlas loading with a bounded-size LRU cache, driving SWCanvas-rendered text. Many text boxes spawn at random positions with random font/style/weight/size, random rotation (Tilt) and uniform scale, and a random short lifetime. The page pulls in atlases as needed, and the LRU evicts and actually unloads old atlases so the resident-atlas count stays bounded — even under N > K stress.

Why it matters. Real apps with large font catalogues can’t hold every atlas in memory. This shows BitmapText.js’s BitmapText.loadFont / BitmapText.unloadAtlas / BitmapText.hasAtlas primitives — vendored verbatim into SWCanvas’s dist — composing into a working memory-bounded loader. SWCanvas wraps the engine with ctx.fillText + ctx.textPixelDensity and renders the slow-path intermediate buffer through its own drawImage so rotation and scale work without any text-engine awareness of transforms.

How. Each TextBox owns a physical-pixel-sized SWCanvas surface (cssSize × pixelDensity) and paints by applying its baked rotation+scale, calling ctx.fillText, then blitting the surface pixels onto a same-sized display <canvas> whose CSS box is at logical size — the browser downsamples for display so density-2 detail is visible under pixel-peep. SWCanvas’s slow path renders text into an intermediate buffer sized at the exact ink bounding box (BitmapText.computeInkBoundingBox) and drawImages it with the current transform. Atlas-warmth is checked post-paint via BitmapText.hasAtlas; if either the primary or invariant atlas (for the smiley) is missing, the LRU’s load promise is attached, with dirty.add(this) on resolve so the box repaints when bytes arrive. Atlases-resident in the stats reads AtlasDataStore.size() directly, so it physically can’t exceed K. The race where a freshly-loaded atlas could be evicted before its requester paints is defused by a 250 ms pin window on every recent touch and load completion. The FPS histogram (last 120 frames, color-coded by frame budget) makes any reconstruction-induced jank directly visible.

Minimum-set bundle loading. The demo proactively loads only the positioning bundle the current DPR configuration needs (e.g. on a 1x screen in Auto mode, only positioning-bundle-density-1.js). The Bundles loaded row above shows live state for each bundle. Toggling the DPR dropdown — or dragging the window between monitors of different physical pixel density while in Auto — triggers a unified config-change path that retires textboxes + LRU entries of the removed density, then calls BitmapText.unloadPositioningBundle(d) to clear records, drop cached promises, and detach the injected <script> from document.head. The newly-needed bundle is fetched in parallel. SWCanvas-specific controls (Tilt, Scale, Transparent bg) exercise the rotation/scale slow path and the alpha pipeline.
